# VIIT AI Feedback

React and Vite college administration interface. The homepage retains the supplied Framer template. The admin portal uses the VIIT logo, readable cards, and a navigation drawer that opens on demand. No AI calling or telephony is connected.

## Run

```sh
npm install
npm run dev
```

The homepage is `/`; the protected portal is `/admin`. Static hosting must serve `index.html` for `/admin`. `npm run build` generates `dist/`.

### Vercel

Keep `vercel.json` beside `package.json` in the Vercel project root. It selects Vite, builds into `dist`, and rewrites client routes such as `/admin` to `index.html`, so direct links and refreshes work. Commit and push this file with the source, then deploy the new commit; redeploying an older commit will not include the fix.

Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` in the Vercel project's environment variables for the deployment environment before building. Local `.env` files remain ignored. No secret/service-role key is needed on Vercel for this frontend.

## Supabase setup and upgrades

1. Set these public values in `.env`:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
   ```

   A legacy anon key is also accepted. Never put a service role key, secret key, or password in a `VITE_*` variable.
2. Create a confirmed email/password account in Supabase Authentication. Run `supabase/setup-admin.sql` with that account's email to assign the trusted admin role. Sign out and back in after changing the role.
3. Run the **complete current `supabase/schema.sql`** in the project's SQL Editor. It can be rerun and preserves existing records. This also applies upgrades: the Faculty table and `college_dashboard` summary function are included.
4. Restart Vite after changing environment values.

The public API key cannot create tables or SQL functions. Missing database objects display a setup error; the app does not pretend an unsuccessful save worked. RLS restricts all records and aggregate summaries to trusted admins. Activity entries are generated by database triggers and cannot be edited by browser clients.

## Administration

- **Dashboard:** college totals, activity trend (7/30/90 days), attendance breakdown, feedback status, prepared communication setups, branch distribution, and paginated history across all sections. Select a history entry's class to open that section. Date boundaries use Asia/Kolkata. Attendance counts marked student-days, not unique students. Feedback and setup charts are all time. Counters and chart fills animate from zero after data loads, with hover details and reduced-motion support. Zero-data states are real; no example statistics are inserted.
- **Navigation:** hamburger > Branches > branch dropdown > year > section. Selecting a section closes the drawer and opens its page, with Calling, Mentoring & attendance, Feedback, Students, and saved setups inside the page. Changing branch/year clears the previous section. The main Branches page still offers Add branch and Add section.
- **Students:** upload CSV/XLSX, validate and edit, confirm, and save to the selected section. Existing student IDs are protected from overwrites. Lists can be exported.
- **Attendance:** manually mark present, absent, or late for a date, then save. Failed saves retain pending changes.
- **Feedback:** record a concern and move it from pending to reviewed to resolved.
- **Calling:** prepare student lists, questions, and preferences; save the setup. Start calling remains disabled. There are no fabricated responses, transcripts, or call summaries.
- **Faculty:** add and view name, email, branch, and designation; search or filter by branch. Faculty email addresses are unique, ignoring case.

Branches, sections, students, attendance, feedback, communication setups, activity history, and faculty are saved in Supabase. Unsaved forms do not survive a page reload. Older browser-local campaign records are not automatically imported into these tables.

## Upload format

CSV or first worksheet of XLSX, up to 5 MB / 5,000 students per upload. Required columns: `student_id`, `student_name`, `parent_name`, `phone`. Optional columns: `attendance`, `marks`, `language`, `feedback_topic`.

Phone numbers must be valid Indian mobile numbers. Attendance/marks range from 0 to 100. Supported languages: English and Telugu. Feedback topics: Class, Hostel, Bus. Mentoring setups require attendance; feedback setups require a topic. Questions allow 1-10 entries, up to 300 characters each. Call preferences are configuration only.

## Verification

```sh
npm test
npm run test:ui
npm run build
```

Tests cover upload validation, export, authorization, navigation, form recovery, history, faculty, and communication setup. The schema runs twice against an isolated PostgreSQL engine with RLS and trigger checks, including aggregate summaries and faculty constraints. UI tests use mocked Supabase requests; they do not place calls or change the live project. Browser visual verification depends on preview access.
